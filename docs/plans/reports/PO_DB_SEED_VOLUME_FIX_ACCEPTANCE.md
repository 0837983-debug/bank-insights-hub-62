# Product Owner Acceptance: DB_SEED_VOLUME_FIX — единый путь `db:seed` в Docker

## Вердикт
ACCEPTED

## Проверенные сценарии
- [x] Заказчик пересевает тестовые CSV одной compose-командой без знания путей к volume (`A.7`, `B.6` в `customer-docker-run.md`)
- [x] В документации явно разделены тестовый seed и prod-данные через UI `/upload`
- [x] `db-seed` работает без CLI `-v` workaround (подтверждено QA E2E и конфигурацией compose)
- [x] Предусловия и критерий успеха понятны нетехническому пользователю (схема уже есть → одна команда → `Seed completed successfully`)

## Что хорошо
- **Одна каноническая команда** для dev и prod-like сценариев — заказчику не нужно искать абсолютные пути или монтировать volume вручную:
  - dev: `docker compose -f docker-compose.dev.yml --profile seed run --rm db-seed`
  - prod-like: `docker compose -f docker-compose.prod.yml --profile seed run --rm db-seed`
- **Секция A.7** в `customer-docker-run.md` хорошо структурирована: когда использовать, что происходит (таблица), как понять успех, отдельные callout для prod (`/upload`) и Windows.
- **Разделение ролей seed vs upload** последовательно: в `customer-docker-run.md`, `docker.md` (таблица bootstrap/migrate/seed) и callout'ах — prod-файлы только через `/upload` с валидацией.
- **Предупреждение про `-v` в CLI** снимает типичную ловушку на Windows Git Bash — пользователю сказано, чего *не* делать, и дана альтернатива.
- **QA** подтвердил end-to-end: exit 0, `Seed completed successfully`, `mart.fin_results` = 30 строк, регресс smoke 11/11.

## Что не устраивает

Существенных замечаний нет.

### Наблюдение (minor, не блокирует приёмку): B.6 короче A.7
**Где:** `docs/guides/customer-docker-run.md`, раздел B.6  
**Почему может мешать:** в prod-like варианте нет таблицы «что происходит» и Windows-подсказки, как в A.7.  
**Ожидаемое поведение:** тот же уровень ясности, что в dev-секции.  
**Фактическое поведение:** одна команда + одна строка про `/upload` — достаточно для основного сценария.  
**Критичность:** minor

- Нет обязательных доработок.

## Итог
Задача решает исходную пользовательскую проблему: заказчик и CI могут пересевать тестовые CSV из репозитория одной compose-командой, без знания путей и без обходных `-v`. Документация однозначно направляет реальные production-данные в UI `/upload`. Приёмка пройдена.
