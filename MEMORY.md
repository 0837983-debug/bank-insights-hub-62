# MEMORY

Ключевые сведения, которые необходимо помнить при работе с данным репозиторием.

## Ежедневные отчёты
- Каждый рабочий день записывать работу в отдельный текстовый файл внутри папки `daily-reports/`.
- Имя файла — дата дня в формате `ДД-ММ-ГГГГ.txt` (например, `07-08-2026.txt`).
- Файлы ведутся в едином формате: «ОТЧЁТ О РАБОТЕ ЗА ...», разделы по пунктам.
- В течение дня отчёт дополняется компактно, не раздувая файл.
- Фиксация отчётов в git — ТОЛЬКО строго в конце рабочего дня, а не по ходу.
- После создания/правки отчётов сверять содержимое и при необходимости перечитывать файлы.

## Процесс (договорённости)
- ОБЯЗАТЕЛЬНО спрашивать у пользователя разрешение на фиксацию (git commit) — не коммитить без явного согласия.
- Ветка разработки — `dev`. Готовые ветки (feature/*) сливаются в `dev` по указанию пользователя, после этого рабочая ветка — `dev`, из неё создаются новые.
- Прямые коммиты/правки в `dev` и `main` запрещены (блокирует pre-commit хук scripts/block-protected-commit.mjs). Вся работа — только через feature-ветки и последующее слияние.
- Защитный контур Husky перед слиянием/пушем в dev/main: 1) статические проверки (tsc --noEmit + eslint, scripts/run-static-checks.mjs), 2) пакетные e2e-тесты на изолированном контуре (scripts/test-runner.mjs). При любой ошибке операция блокируется.
