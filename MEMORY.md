# MEMORY

Ключевые сведения, которые необходимо помнить при работе с данным репозиторием.

## Ежедневные отчёты
- Каждый рабочий день записывать работу в отдельный текстовый файл внутри папки `daily-reports/`.
- Имя файла — дата дня в формате `ДД-ММ-ГГГГ.txt` (например, `07-08-2026.txt`).
- Файлы ведутся в едином формате: «ОТЧЁТ О РАБОТЕ ЗА ...», разделы по пунктам.
- В течение дня отчёт дополняется компактно, не раздувая файл.
- Фиксация отчётов в git — ТОЛЬКО строго в конце рабочего дня, а не по ходу.
- После создания/правки отчётов сверять содержимое и при необходимости перечитывать файлы.

## E2E-тесты и авторизация
- Единый центр входа: `e2e/helpers/auth.ts` (логин, токен), `e2e/fixtures.ts` (adminToken, authedRequest), `e2e/global-setup.ts` (токен один раз на прогон в `.auth/access-token`).
- UI-тесты логинятся через `loginAsAdmin(page)` в beforeEach; API-тесты используют `authedRequest` (Bearer подставляется автоматически).
- Лимит входов логина `AUTH_LOGIN_MAX` (по умолчанию 20/15мин) в dev увеличен до 2000 для E2E; в проде задаётся отдельно.
- Все не-docker E2E проходят (142/142). docker-спеки (docker-smoke, docker-db-seed) выполняют db:reset — запускаются изолированно, стирают seed-данные.
- Формат ошибок API — единый {code, message, details} (карта ошибок). Откат загрузки и формат файла (400) исправлены.
